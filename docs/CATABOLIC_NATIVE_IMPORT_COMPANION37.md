# Exact companion cleanup admission for native import

This is an additive native37 admission qualification for bounded import V2. It
requires the complete corrected R5 companion/storage/runtime slice. It adds no
schema and does not modify schemas 1–37 or any native signature. The independent
R4 private-writer37 qualification is not implied by this Store import contract.

## Required conjunction

Activation remains inside the existing command transaction and retains the exact
closed/drained common HostAuthorization through COMMIT. It now requires all of:

1. The existing migration owner's native pending-work inventory is settled.
   Pending processing/refresh/consumer/API/observation queues, execution claims,
   owned execution lifetimes and unfinished companion reservations still refuse.
2. The complete native worker inventory admits new work. Its 4,096 inspected-owner
   and 256 unresolved-output bounds must not truncate. A positive observation
   witness cannot waive unrelated terminal processing, watcher, probe or API
   ownership, and cannot bypass a late unknown owner.
3. No retained watcher pointer exists. For every retained observation pointer,
   the schema must be exactly the qualified companion schema37 and
   native_observation_companion::has_cleanup_witness must accept that exact job.
   Older and unknown owners remain refused. PIDs are never cleared or adopted.
4. The existing rollback-journal requirement, final validation generation,
   complete mapping digest and explicit trusted source/reference acknowledgment
   still match. Real WAL/restore and external effects are not enabled.

The full worker inventory also applies conservatively to older supported native
imports. A terminal row without a supported exact witness does not become settled
just because its PID is absent, its lease expired, or an unrelated process exited.
The subsequent retained-pointer query is bounded by that already-complete
inventory and executes in the same writer transaction.

## What the observation proof means

The only positive predicate is owned by the exact R5 companion protocol. The
trusted packaging grant must identify the already-qualified implementation and
capability. Hashing an arbitrary executable does not qualify it. Reservation,
actual child admission, complete acknowledgment, retained Child exit/reap and the
runtime-private tuple-exact seal all precede this import predicate. A shared
consumer's seal cannot settle the original execution owner. A changed current
claim invalidates an old seal.

The runtime fixture uses a fresh explicitly unenrolled source. It does not remove
or disable an existing source's required UUID policy. Closed helpers continue to
refuse required UUID-child checks and all unqualified helper paths.

## Fixture boundaries

The actual-helper positive case imports a physically observed exact occurrence
and creates its explicit association, provisional timeline and draft version via
existing owners. The file has unknown media duration, so coverage and placement
remain absent and the version stays draft. No duration, readiness, interval
coverage or editorial equivalence is invented. Equal-content physical duplicates
remain separate. The original terminal job PID and exact companion witness stay
recorded after activation and receipt-only replay.

Negative actual-helper cases preserve a positive observation witness while adding
unrelated pending processing, unwitnessed terminal processing or an unknown API
owner; each must refuse activation. A separate changed-claim case proves a former
seal cannot authorize a new owner. No negative fixture writes a cleanup seal or
clears an ownership pointer.

Existing bounded import fixtures explicitly retain native34/35/36 coverage and
add native37 metadata/pin, exact identity, rollback and before/after-commit process
exit cohorts. Those synthetic identity fixtures remain separate from the actual
scanned-source qualification. External Motion export/reference migration,
independent blocked reviews, real WAL/restore/destructive publication and interval
media effects remain outside this addendum.
