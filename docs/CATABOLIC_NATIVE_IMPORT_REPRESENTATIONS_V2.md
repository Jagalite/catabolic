# Bounded V2 import representation qualification

This development addendum qualifies additional supported snapshot representations
through the existing V2 import adapter on disposable native schemas 34–37. It
changes no production owner, native schema, receipt protocol, or external
application integration. The earlier restart and mixed-owner receipt retains its
original source and evidence boundary; this is an incremental source cohort.

## Native identity representations

`native_import_staging::representations` imports one edition with:

- Two complete alternative two-part versions, each with a dedicated association
  item and its own consecutive parts 1 and 2
- One shared established theatrical timeline whose equivalence declaration names
  both versions, timeline/version revisions, and every exact physical revision
- A distinct cut on a separate provisional timeline with different coverage
- An encode of unknown equivalence on another provisional timeline, even though
  its title, fixture bytes, and declared coverage match the theatrical version

The six pre-established occurrences use real file stat values and explicit,
quiescent fixture observation rows. Durations and equivalence are declared
fixture input, not probe-derived measurements or evidence of scan cleanup. Source
availability stays unknown. No content equality establishes native equivalence.

Single-batch and cross-batch snapshots exercise source association IDs through
curation-generated destination IDs and exact bindings. The cross-batch shape puts
physical mappings and associations before their consuming native mutation. Tests
compare all owner mapping families, reconstruct the full canonical V2 mapping
digest, verify exact revision/evidence retention, and compare validated mappings
with committed results. A logical-only digest or an edited association map refuses
activation. Source association strings do not become persisted binding IDs.

Validation leaves items, search documents, associations, contexts, histories,
timelines, versions, bindings, and evidence invisible and generation unchanged.
Activation commits all four shapes. Reopen replays the original intent with new
commands disabled and without mutation grants or a new freeze. No histories,
receipts, or holds are duplicated. The existing whole-version selection decision
is exercised on imported manifests: complementary available parts from different
alternatives cannot combine; one entirely available alternative is selected.
An unknown-equivalence version remains explicitly selectable on its own timeline
and cannot be treated as a theatrical equivalent. These availability inputs are
decision fixtures, not an assertion of live filesystem availability or playback.

Missing evidence, stale declared version evidence, a cross-version source
association, denied declaration authority, and a replaced occurrence after
validation refuse without partial identity writes. A late receipt trigger proves
all six bindings, all four versions, and declared evidence were already written
before failure; rollback removes their histories, item projections, search,
generation changes, receipts, and holds. Retrying the original activation after
removing the injected fault succeeds with the same reviewed mapping.

## Metadata source semantics

`native_import_staging::contribution_semantics` exercises current contribution
documents from local, provider, and scan namespaces with independently supplied
source-kind grants. Local values, including explicit null for a nullable field,
retain the existing owner's precedence over legacy and external sources. Absent
fields are not manufactured into nulls. Legacy values and provenance remain
retained under the existing resolution rules.

The tests check validation invisibility, exact projected values, source revisions
and evidence, replay after reopen, unknown-field, nullability, multiple-local-source, and exact source-grant refusal,
stale activation, and atomic rollback after owner writes. Empty scan documents
and explicit null at every precedence tier remain distinct from absent fields.
Each imported current source revision maps explicitly to new Catabolic revision
1. A post-import owner mutation rejects exported-revision CAS, advances the actual
head from revision 1 to 2, and removes the local override to reveal retained legacy
without reconciliation. These tests do not invent missing prior source history
or qualify a source-history reconstruction adapter.

## Evidence and unchanged limits

The exact source manifest, standard Rust 1.99.0 toolchain, locked offline commands,
terminal results, executables, incremental patch and full adoption files accompany
this addendum. The source-bound receipt records final test counts and all failed
attempts, if any. This is development qualification, not independent review or a
full-workspace/release gate.

No tags/suppression, retirement/merge/split history, unsupported legacy semantic
adapter, source bootstrap, external reference rewrite, or unlimited catalog
migration is added. Unknown/missing facts are not guessed. Existing bounded
snapshot and owner budgets still apply. Actual Motion persistence, reference
updates, two-owner deployment, real WAL cutover, backup/restore publication,
destructive filesystem publication, interval media effects, non-Linux/release
gates, and the blocked independent reviews remain deferred or fail closed.
